# P1 发布与回滚说明

## 发布前验证

1. `web` 执行 `npm ci`、`npm run typecheck`、`npm run test:coverage`、`npm run build`。
2. `cloudfunctions/sherlock-api` 执行 `npm ci`、`npm run test:coverage`。
3. 读取 `family24` 套餐、到期时间、当期剩余额度和超额付费开关。
4. 确认 24 点 URL 返回 200，远端 11 个当前文件与本地 `D:\project_antigravity\24\dist` 匹配。
5. 确认所有待写资源都匹配 `sherlock-*`、`sherlock_*` 或 `sherlock-english/*`。

## 发布顺序

1. 创建缺失的 `ADMINONLY` 数据库集合。
2. 部署 Event 云函数 `sherlock-api`，运行 `health` 检查。
3. 使用本地受控配置生成家长密码 scrypt 哈希与会话 HMAC key，并配置到云函数环境变量。
4. 使用环境 ID 与前端 `publish_key` 构建 `web/dist`；真实值不得写入 Git。
5. 仅上传 `web/dist` 到静态托管 `sherlock-english/` 子目录。
6. 写入一条 `P1-SMOKE` test 记录，核对 `data_kind=test` 与 `formal_completion_eligible=false`。
7. 再次核对 24 点、套餐、超额付费与资源点。

## 回滚

- 静态站：只删除或覆盖 `sherlock-english/` 子目录，禁止操作托管根目录。
- 云函数：删除 `sherlock-api` 或重新部署上一份 P1 代码；禁止删除其他函数。
- 数据库：P1 验收记录先导出再处理；不得通过删除数据修复问题。
- 身份认证：若 P1 完全回滚且确认无其他系统使用匿名登录，可恢复到 P1 前的 `AnonymousLogin=false`；其余登录开关保持原值。
- 24 点回滚基准：`family24-web-003`；静态文件基准为本地 `D:\project_antigravity\24\dist` 的 11/11 匹配结果。

任何回滚操作执行前，都必须重新列出精确目标并确认不包含 24 点资源。
