# P4 数据迁移与家长端

> 目标：迁移历史正式证据并完成对账，让家长端可区分、查询和审计 formal/test。

## 进入条件

- P3 验证门通过；
- 已获得原私有结果库和录音的只读访问；
- 已确认历史数据来源、课程 ID 和 `data_kind` 解释规则；
- CloudBase 数据库与存储备份/导出方法已验证。

## 本阶段范围

- 家长认证和结果查询；
- 听力、口语 formal/test 明细展示；
- 历史成绩、错题、订正、弱词、尝试星级和录音迁移；
- 迁移前后数量、字段、时间、文件和 SHA-256 对账；
- 原私有结果库保留只读。

## 迁移原则

- 原始数据不可改写；
- 先导出和哈希，再转换和导入；
- formal/test 必须逐条有证据；
- 缺少 `data_kind` 的记录默认 test，除非正式来源可验证；
- 迁移脚本可重复执行且不重复创建记录；
- 录音在对账完成前不得从任何原位置删除。

## 实施步骤

1. 导出旧结果索引、完成状态、听力明细、口语明细、录音清单和课程版本映射。
2. 生成原始快照、数量、总字节数和 SHA-256 清单。
3. 建立旧课程 ID 到新课程/历史课程 ID 的映射，不把旧正式记录伪装成新学期课程。
4. 编写只追加、幂等的转换与导入脚本；保留 `legacy_source_id` 和迁移批次号。
5. 导入 CloudBase 隔离集合和私有存储。
6. 对账每种 module/data_kind 的记录数、关键字段、时间、录音数量和哈希。
7. 在家长端按 formal/test 过滤，展示课程、时间、听力错题/订正、口语星级/弱词/门控和录音。
8. 抽样核对若干原记录与新页面；生成差异报告。

## 家长端要求

- 密码哈希验证和会话过期；
- formal/test 有明显标签和独立筛选；
- 默认不把 test 混入正式汇总；
- 可按模块、课程和时间查询；
- 可查看 `wrong_answers`、`section_scores`、`corrections`；
- 可查看 `question_results`、`weak_words`、`take_stars`、`passed_by_safety`；
- 录音使用短期受控地址，不公开永久 URL。

## 验证门

- 导入脚本重复运行无重复记录；
- 原始数量、成功导入、跳过和异常数量可相加对账；
- formal/test 汇总与逐条记录一致；
- test 不进入完成状态和正式分析；
- 录音数量与抽样 SHA-256 一致；
- 家长端桌面与 iPad 查询通过；
- 原结果库和录音保持未删除、只读可恢复。

## 交付物

- 迁移脚本和字段映射；
- 原始快照与哈希清单；
- 迁移对账报告和异常清单；
- 家长端；
- 原私有库只读保留说明；
- 更新后的状态文档。
