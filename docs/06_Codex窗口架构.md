# Codex 窗口架构与协作规则

## 1. 长期窗口

### 00 英语系统总控与路线图

负责方向、优先级、学校进度、跨模块决策、新功能立项和阶段验收。不直接承担大量代码实现。

### 01 教材与课程内容开发

负责教材页段校对、study pack、听力/跟读课程内容、音频文本和 A 主线 + C 微调。不读取 test 形成学情。

### 02 系统开发与 CloudBase 运维

负责代码、CloudBase、讯飞、自动测试、音频生成流水线、部署、监控和故障处理。

### 03 正式学情与数据分析

只读取 formal 成绩、错题、订正、弱词和录音明细，形成证据有边界的分析。不得修改课程或生产数据。

## 2. 临时窗口

命名格式：

```text
CAP-功能名
REL-日期-版本
BUG-问题名
AUDIT-审计主题
```

临时窗口必须有明确退出条件，完成后归档。音频完整性检查属于 02 的自动测试，不再设长期窗口。

## 3. 文件是事实源

窗口开始时读取：

1. `AGENTS.md`；
2. `docs/00_项目总计划.md`；
3. `docs/01_已确认决策.md`；
4. `docs/02_PROJECT_STATUS.md`；
5. 自己的窗口指令；
6. 当前阶段计划。

聊天中的旧结论与文件冲突时，以当前文件和用户最新指令为准。

## 4. 责任边界

- 总控可以批准或拒绝阶段进入，不直接替代开发测试。
- 内容窗口写课程前必须拿到教材范围，不猜学校进度。
- 开发窗口不根据测试成绩创建学情结论。
- 数据窗口不把口语星级等同于词义掌握。
- 任一窗口发现 formal/test 串写风险时，立即停止生产写入并报告。

## 5. 状态更新

完成有持久影响的工作后更新 `02_PROJECT_STATUS.md`。重大新决定追加到 `01_已确认决策.md`，不得静默改变已锁定决策。

## 6. 窗口切换建议

- 本次新开 `02 系统开发与 CloudBase 运维` 执行 P0。
- P0 完成后继续由 02 执行 P1 至 P5，无需每阶段重开长期窗口。
- 课程内容需要新增时，再打开 01。
- 需要分析正式结果时，再打开 03。
- 新功能讨论先在 00，批准后创建临时 `CAP-*` 窗口。
