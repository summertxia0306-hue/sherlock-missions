# Codex 窗口架构与协作规则

> 2026-08-28 家长确认：采用新的四窗口架构。原“03 正式学情与数据分析”并入 00，由新的“03 学校练习与考试批改归档”替代。

## 1. 长期窗口

### 00 英语系统总控、学情分析与路线图

负责方向、优先级、学校进度、跨模块决策、线上 formal 分析、校内证据综合、学习档案维护、新功能立项和阶段验收。

00 是《夏洛恪_英语学习档案》的唯一维护者。它读取 CloudBase formal 数据和 03 的校内错题库，但不逐张批改学校材料，不替代 01 大批开发课程，也不替代 02 做工程发布。

### 01 教材与课程内容开发

负责教材页段校对、study pack、听力/跟读课程内容、音频文本和 A 主线 + C 微调。弱项来源只认 00 确认的摘要，不从 test 或原始学生材料自行形成学情。

### 02 系统开发与 CloudBase 运维

负责代码、CloudBase、讯飞、自动测试、音频生成流水线、部署、监控和故障处理。不得读取、上传或部署 `private/` 内的学生材料。

### 03 学校练习与考试批改归档

负责接收学校练习、测验和考试照片/扫描件，保存原始证据，逐题批改，区分知识错误、粗心/书写与待确认项，维护校内错题库及订正状态，并向 00 提供批次摘要。

03 是校内错题库的唯一维护者，不修改学习档案、课程或生产数据。

## 2. 单一写入责任

| 数据/文件 | 唯一维护窗口 |
|---|---|
| 《夏洛恪_英语学习档案》 | 00 |
| 校内错题库、学校材料批改记录 | 03 |
| 课程内容、教材映射、音频文本 | 01 |
| 程序、CloudBase、部署与运维记录 | 02 |

学校材料与学习档案统一存入本地 `private/`，不得进入公开 Git。

## 3. 两条固定路线

线上正式学习：

```text
CloudBase formal → 00 分析并更新学习档案 → 01 内容开发 → 02 测试发布
```

学校材料：

```text
照片/扫描件 → 03 批改并写错题库 → 00 更新学习档案 → 必要时 01/02
```

单次错误默认留在错题库；重复错误、订正后仍错或跨场景出现的模式，才由 00 判断是否进入长期能力画像。

## 4. 工作频次

| 窗口 | 默认频次 |
|---|---|
| 00 | 每周一次；重要考试后立即；每批新课程前 |
| 01 | 默认每周一组；每 2–4 周按学校进度规划一批 |
| 02 | 每次发布或故障；每月检查 CloudBase 与讯飞额度 |
| 03 | 每收到一批学校材料即处理；订正材料到达时更新原错题 |

## 5. 临时窗口

命名格式：

```text
CAP-功能名
REL-日期-版本
BUG-问题名
AUDIT-审计主题
```

临时窗口必须有明确退出条件，完成后归档。大规模历史学情对账或专项分析使用 `AUDIT-学情-*`，不恢复常驻分析窗口。

## 6. 文件是事实源

窗口开始时读取：

1. `AGENTS.md`；
2. `docs/00_项目总计划.md`；
3. `docs/01_已确认决策.md`；
4. `docs/02_PROJECT_STATUS.md`；
5. 自己的窗口指令；
6. 当前阶段计划；
7. 仅限职责所需的私密资料。

聊天中的旧结论与文件冲突时，以当前文件和用户最新指令为准。

## 7. 功能范围

当前核心功能只有教材总控、听力/跟读课程、CloudBase PWA、formal 学情、学校材料批改、校内错题库和学习档案。

背单词、自动出纸面卷、互动课件、ChatGPT 陪练及其他新增功能只有在家长回到 00 明确立项后才能讨论设计或开发。

## 8. 状态更新

完成有持久影响的工作后更新 `docs/02_PROJECT_STATUS.md`。重大新决定追加到 `docs/01_已确认决策.md`，不得静默改变已锁定决策。
