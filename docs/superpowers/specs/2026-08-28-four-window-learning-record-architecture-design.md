# 夏洛恪英语项目四窗口与学习记录架构设计

> 日期：2026-08-28  
> 状态：家长已批准  
> 适用根目录：`D:\ObsidianVaults\Education\Sherlock\English-Learning`

## 1. 决策摘要

项目采用四个长期 Codex 窗口：

1. `00 英语系统总控、学情分析与路线图`
2. `01 教材与课程内容开发`
3. `02 系统开发与 CloudBase 运维`
4. `03 学校练习与考试批改归档`

原长期窗口 `03 正式学情与数据分析` 的职责并入 00，不再单独保留。遇到大规模历史对账或专项学情审计时，按需创建 `AUDIT-学情-*` 临时窗口，完成后归档。

当前核心范围只有：

- 以学校实际教材进度为主线；
- 听力与跟读/口语课程的持续运营；
- CloudBase PWA 的开发、发布和运维；
- 线上正式学习数据分析；
- 学校练习与考试材料的批改、证据归档和错题库；
- 由 00 维护的唯一权威学习档案。

背单词、自动出纸面卷、互动课件、ChatGPT 陪练以及其他新增功能均不属于当前核心范围。未来只有在家长重新讨论并明确立项后才能进入设计或开发。

## 2. 窗口职责

### 00 英语系统总控、学情分析与路线图

- 管理方向、优先级、阶段进入与退出；
- 确认学校实际教材范围和每批课程目标；
- 读取并分析 CloudBase `formal` 数据；
- 读取 03 维护的校内错题库；
- 综合线上和校内证据，维护唯一权威《夏洛恪_英语学习档案》；
- 判断哪些重复弱项进入 A 主线 + C 微调；
- 向 01、02 派发内容和发布任务；
- 对费用、孩子负担、正式数据和新功能范围作总控决策。

00 不逐张批改学校材料，不替代 01 大批生成课程，也不替代 02 做大量工程实现。

### 01 教材与课程内容开发

- 按 00 确认的 4A 教材页段开发同轨听力和跟读课程；
- 默认约 80% 学校教材主线、20% 经 00 确认的弱项复现；
- 维护课程 JSON、教材映射、家长版原文答案和音频文本；
- 完成内容、schema、答案、音频和教材范围校验。

01 不自行判断学校进度，不直接读取原始学生照片，不修改学习档案或校内错题库。

### 02 系统开发与 CloudBase 运维

- 负责 PWA、CloudBase、讯飞、自动测试、部署和故障处理；
- 维护 formal/test 隔离、认证、数据安全、录音和家长端；
- 执行发布验证、iPad 验收支持、资源点和额度检查。

02 不把测试结果写成学情，不维护学习档案或错题库。

### 03 学校练习与考试批改归档

- 接收家长上传的学校练习、测验和考试照片或扫描件；
- 保存不可变原始证据并记录来源、日期、材料类型和文件哈希；
- 逐题批改，区分知识错误、粗心/书写问题和无法确认项；
- 维护题目级校内错题库及订正状态；
- 每批生成给 00 使用的批改摘要和待吸收批次标识。

03 不修改《夏洛恪_英语学习档案》，不直接修改课程，不把模糊题面或不可靠答案写成正式能力结论。

## 3. 学习档案与错题库

采用“错题库记事实，学习档案记结论”的单一写入架构：

- 03 是校内错题库的唯一维护窗口；
- 00 是《夏洛恪_英语学习档案》的唯一维护窗口；
- 错题库保存题目级证据；
- 学习档案保存经过综合判断后的长期进度、能力变化、稳定弱项和教学策略；
- 单次偶发错误可以只留在错题库，不自动升级为长期能力弱点；
- 学习档案记录已吸收的最新校内批次或日期，避免遗漏和重复。

证据流：

```text
CloudBase formal ──────────────────────→ 00
                                          ↓
学校照片/扫描件 → 03 → 校内错题库 ────→ 00 → 学习档案
                                          ↓
                                    课程调整决策
                                          ↓
                                    01 内容开发
                                          ↓
                                    02 测试发布
```

## 4. 正式证据边界

- 线上学情只认 `data_kind=formal`；
- `test` 只用于开发和验收；
- 学校材料必须能追溯到原始照片、扫描件或家长明确确认；
- 图片模糊、题干缺失、答案来源不可靠的题目只标记“待确认”；
- 口语星级表示评分模型下的朗读表现，不单独证明词义掌握；
- 单次错误不直接升级为长期弱项；
- 重大结论必须说明证据范围、反例、不确定性，以及“这个判断最可能错在哪”。

## 5. 隐私与存储

学生照片、扫描件、校内错题库和学习档案属于私密学习数据：

- 统一存放在项目内的本地 `private/` 目录；
- `private/` 必须由 `.gitignore` 排除，不进入公开 GitHub 仓库；
- 公开治理文档可以记录规则和目录结构，但不得包含原始学生答卷、逐题隐私记录或私有访问凭证；
- 旧项目的学习档案迁移后继续保留全部历史和 E 编号；
- 旧源文件不删除，作为迁移前只读来源保留。

## 6. 工作频次

| 窗口 | 默认频次 |
|---|---|
| 00 | 每周一次；重要考试后立即；每批新课程开始前 |
| 01 | 默认每周一组课程；每 2–4 周按实际教材进度规划一批 |
| 02 | 每次发布或故障时；每月检查资源和讯飞额度 |
| 03 | 每收到一批学校材料即处理；订正材料到达时更新原错题 |

## 7. 重新拆分条件

只有出现以下情况之一，才重新讨论独立的数据分析窗口：

- 增加多个学生；
- 正式结果量显著增大，00 无法在正常节奏内完成分析；
- 需要独立数据仓库、仪表盘或固定周期分析产品；
- 家长明确要求重新拆分职责。
