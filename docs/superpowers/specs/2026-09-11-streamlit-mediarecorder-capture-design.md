# Streamlit iPad 录音内核替换设计

日期：2026-09-11  
状态：用户已批准方案 A

## 目标

解决 iPad Safari 中口语录音偶发断续、音频块重复却仍被送去评分的问题。保持现有
Streamlit 正式入口、16 kHz WAV、讯飞 ISE、私有录音库、正式/测试数据隔离和课程门控不变。

## 已确认故障证据

- 2026-09-08 的坏录音表现为约 85 ms 全零块与有声块交替。
- 2026-09-10 `S4A-T1-W01-D05` 第 6 题第 1 次录音表现为另一种模式：136 个约
  85 ms 块中，奇数相邻对有 50/68 高度重复，偶数相邻对为 0/67；同题重录为 0/24。
- 当前前端仍以废弃的 `ScriptProcessorNode` 在主线程分块采集，只能识别第一种全零故障，
  因而第二种重复帧会被放行并造成错误低分。

## 方案

1. 浏览器主链路改用原生 `MediaRecorder`，每次录音仍重新申请并结束麦克风流。
2. 停止后将单个录音 Blob 解码为 PCM，再沿用现有逻辑编码成 16 kHz、16 bit、单声道 WAV。
3. 仅在浏览器没有 `MediaRecorder` 时启用旧 `ScriptProcessorNode` 兼容回退。
4. 浏览器编码前检查静音、交替空白和相邻重复帧；失败时立即作废并恢复可点击话筒。
5. Python 评分入口再次校验 WAV 格式、时长、峰值、交替空白及重复帧。失败录音不调用讯飞、
   不上传、不占有效录次，并给孩子显示“设备录音异常，请重录”，不评价发音。

## 验证门槛

- 用合成正常 WAV、交替静音 WAV、重复帧 WAV 做行为测试。
- 用 9 月 9–10 日的 37 段真实录音离线复核：已确认坏样本必须命中，其他正常录音不得误杀。
- 全量 Python 测试、前端 JavaScript 语法、Streamlit 启动及生产页面源码均通过。
- 自动化不能替代 iPad 麦克风硬件。上线后的最终 99% 置信度，以正常课程中连续真实录音
  无断续、服务器复核无异常为最后证据；不要求孩子进入复杂测试页。

## 回滚

单次提交只修改录音组件、评分前完整性校验、契约与测试。若生产异常，可回滚该提交；
历史课程、成绩、录音及结果库均不改写。
