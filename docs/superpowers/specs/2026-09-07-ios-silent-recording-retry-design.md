# iOS 静音录音后话筒可重试修复设计

> 日期：2026-09-07  
> 状态：已实施并上线

## 问题

iPad Safari 在口语题录音结束后若采样峰值低于静音阈值，页面会显示“没有录到声音”。当前代码虽然把状态恢复为 `idle` 并释放麦克风流，但页面上的话筒仍绑定 `stopRecord`。因此第二次点击不会重新申请麦克风，也不会开始倒计时。

## 修复范围

- 仅修改 `speaking/frontend/index.html` 的录音失败恢复流程。
- 静音或录音过短后，释放当前麦克风流，重建话筒按钮，并重新绑定 `onMicTap`。
- 下一次用户点击时重新申请麦克风流，再开始倒计时和录音。
- 保持现有静音阈值、录音编码、评分、录次门控、提交、formal/test 隔离和历史数据不变。

## 失败与数据边界

- 静音或过短录音不生成 WAV，不调用评分接口，不占有效录次，不写入学习结果。
- 修复不读取、修改或删除既有成绩、录音和学习档案。
- 若重新申请麦克风权限失败，继续显示现有权限提示。

## 验证

1. 先添加回归测试，证明当前静音分支不会恢复可点击话筒。
2. 实施最小修复后，验证静音和过短两个分支都会重建话筒并释放流。
3. 运行完整 Python 测试集与静态编译检查。
4. 部署后确认线上口语课程可加载；真实麦克风收音仍以 iPad 实际使用为最终证据。

## 回滚

修复为单文件、单提交变更；若出现回归，可回退该提交，不影响任何学习数据。
