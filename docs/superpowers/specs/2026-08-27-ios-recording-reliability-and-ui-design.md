# iOS 录音可靠性与听读界面微调设计

日期：2026-08-27  
范围：P5 正式入口上线后的缺陷修复；不修改课程内容、成绩、正式进度、test/formal 边界或评分门控。

## 问题与证据

- 两台 iOS 设备均出现首录大概率静音、麦克风橙色图标跨题常亮、回听音量明显偏小；Android 正常。
- 旧 Streamlit 录音没有上述现象。
- 新 PWA 当前跨录次复用 `MediaStream`，成功停止录音后不释放音轨，并显式关闭 `autoGainControl`、`noiseSuppression` 和 `echoCancellation`。
- 旧 Streamlit 录音路径使用浏览器默认音频约束；确认录音后的组件重跑也会结束当次前端录音上下文。

## 修复方案

1. 每次点击录音都重新调用 `getUserMedia`，不复用上一题或上一录次的流。
2. 成功、静音、异常和页面离开时都停止全部音轨；录音结束后 iOS 麦克风图标应熄灭。
3. 录音约束恢复为浏览器默认的回声消除、降噪和自动增益；先不人为放大送给讯飞的 PCM，避免改变评分输入。
4. 保留现有倒计时、最长录音限制、静音拦截、失败不消耗录次、评分重试和三次门控。

## 界面微调

- 当前首个 formal 未完成课程在对应课程卡片显示“推荐”。
- 已完成课程标题与辅助信息置灰，但仍可再次进入。
- “返回本周任务”扩大到至少 48px 触控高度并增加内边距。
- 听力、口语和试音按钮增加高度、行距和按钮间距；窄屏下保持单列，避免文字拥挤。

## 验证

- 先新增录音生命周期回归测试，证明旧实现会复用流且成功后不释放，再实施修复。
- 单元测试覆盖：每次录音新建流、默认音频处理约束、成功/静音/异常均释放音轨、WAV 仍为 16kHz 单声道 PCM。
- 页面测试覆盖：推荐标识、已完成样式、课程仍可进入。
- 执行前端完整测试、覆盖率、TypeScript/Vite 构建和 WebKit/窄屏自动化检查。
- 自动化只能验证浏览器行为与布局；最终仍需一次真实 iOS 录音、回听、评分复验。

## 不在本次范围

- 不改讯飞评分阈值或服务端评分协议。
- 不改课程 JSON、课程开放日期或正式完成状态。
- 不做界面重设计，不增加新功能。

这个判断最可能错在哪：iOS 可能忽略自动增益约束；若释放流并恢复默认音频处理后回听仍偏小，再单独设计只影响回放或有上限的增益处理，不能在本轮未经真机证据直接改评分波形。
