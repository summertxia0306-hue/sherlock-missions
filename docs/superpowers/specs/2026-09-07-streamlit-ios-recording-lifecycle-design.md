# Streamlit iOS 录音生命周期修复设计

> 日期：2026-09-07  
> 状态：家长已批准方案 A，实施中

## 现象与根因

iPad 在口语录音后回放出现断续，讯飞只识别部分单词并连续判低分。当前 Streamlit 录音组件沿用 2026-06-13 的旧策略：成功录音后保留仍为 `live` 的麦克风流，下次录音继续复用。iOS 在示范音、麦克风和录音回放之间切换音频会话时，流可能表面存活但采集质量异常。

CloudBase/PWA 于提交 `419e669` 已改为每次录音重新获取麦克风流、停止后立即停轨，并恢复自动增益、降噪和回声消除。本修复只把该已验证策略移植回 Streamlit 录音组件。

## 实施范围

- 仅修改 `speaking/frontend/index.html` 及对应回归测试。
- 每次开始录音前释放旧流，并调用新的 `getUserMedia`。
- 录音约束固定为单声道，并开启 `echoCancellation`、`noiseSuppression`、`autoGainControl`。
- 停止录音时，无论成功、静音、过短或处理异常，都断开采集节点并立即停止麦克风轨道，再进入回放。
- 保留单一 `AudioContext`，只暂停、不关闭；继续在用户点击调用栈中创建或恢复。

## 不变项

- 不修改 WAV 16kHz/16bit/单声道编码。
- 不修改讯飞评分文本、评分阈值、三星门控或最多三次规则。
- 不修改 formal/test 隔离、上传、结果和学习档案。
- 本次故障产生的 0 星不作为学习能力结论。

## 验证

1. 先添加回归测试，约束“每次取新流、使用音频增强约束、停止即释放”。
2. 运行完整 Python 测试和静态编译。
3. 推送后检查线上组件包含新版策略，并在浏览器运行态模拟成功停止，确认麦克风流已释放且录音可回放。
4. 不自动调用真实麦克风、讯飞评分或正式提交；iPad 实际录音由家长最终确认。

## 风险与回滚

历史上 Streamlit iOS 曾在每次新取流时偶发重复权限提示；当前实现保持同一个组件 iframe 和同一个 `AudioContext`，浏览器通常会复用已授予权限。如果实际设备仍重复弹窗，可单独回滚本提交，不影响学习数据。
