# 口语评分直传 TEST 集成设计

> 日期：2026-09-01
>
> 状态：设计已口头批准，待书面规格复核
>
> 唯一项目根：`D:\ObsidianVaults\Education\Sherlock\English-Learning`

## 1. 背景与决策

此前的隔离探针已经证明：无 VPN Android Chrome 与 iPad Safari 能够从 GitHub Pages Origin 将 150KiB、400KiB 和 700KB 原始 WAV 直接上传到私有 CloudBase/COS，并由服务端完成大小、SHA-256 和清理核验。

该结果只证明传输层可行，并未覆盖真实录音、讯飞 ISE 评分、评分幂等、最终私有录音归档和课程最终提交。本阶段采用分阶段方案：先只在 GitHub Pages 家长 TEST 口语入口接入真实直传评分，保留现有 Base64 分块链路作为自动兜底；通过完整 iPad TEST 验收后，再决定是否另行设计正式入口切换或更深层的评分存储优化。

## 2. 目标与非目标

### 目标

- 在 GitHub Pages 家长 TEST 口语入口中，以私有 COS 直传作为默认录音传输方式；
- 复用现有评分、幂等、次数控制和 TEST 结果持久化逻辑；
- 在安全条件明确时自动回退到现有分块上传，且不要求孩子重新录音；
- 提供仅家长 TEST 可见的传输方式与分阶段耗时诊断；
- 用无 VPN iPad 完成整节 8 题真实 TEST 验收；
- 以真实评分数据判断是否值得进行更深层的评分存储改造。

### 非目标

- 不切换腾讯云正式入口或孩子正式课程；
- 不修改听力链路；
- 不关闭、删除或重写现有分块上传链路；
- 不修改讯飞评分规则、评分阈值、题目内容或课程次数规则；
- 不把 TEST 成绩、录音或诊断数据写入学习档案或正式能力分析；
- 不在本阶段消除评分服务内部全部存储读写；
- 不升级 CloudBase 套餐、开启超额付费或增加公开存储权限。

## 3. 方案选择

### A. 保守直传集成

浏览器把录音直接上传到私有 COS 临时对象，后端下载并核验后，将录音交给现有评分函数；评分成功后沿用现有正式私有录音写入逻辑，并删除临时对象。

优点是改动面最小，能够复用已经验收的评分与归档逻辑；缺点是后端仍存在临时对象下载和最终录音再次写入，提速幅度不能仅凭传输探针推断。

### B. 深层存储改造

浏览器直接写入最终私有录音位置，评分函数直接读取同一对象，避免重复上传。理论上性能更好，但会同时改变评分函数输入、最终录音归档、失败清理和幂等边界，风险明显更高。

### C. 分阶段实施（本阶段选定）

先在家长 TEST 中实施 A，并保留分块自动兜底。完成整节 8 题 iPad 验收后：

- 若稳定性和性能均达标，再另行决定正式入口切换；
- 若稳定但性能未达标，保留 TEST，不切正式入口，并另写 B 的设计；
- 若稳定性未达标，关闭直传开关，继续使用现有分块链路。

## 4. 数据流与接口边界

```text
家长认证的 GitHub Pages TEST 口语页
        |
        | 录音结束：计算 byte_length 与 sha256
        v
sherlock-api：申请一次性真实口语上传票据
        |
        | 返回 120 秒、单对象、最小权限 PUT 地址
        v
浏览器 PUT 原始 WAV 到私有 COS 临时对象
        |
        | 同一 takeId 请求直传录音评分
        v
sherlock-api
        |
        | 重新校验会话、票据、题目、对象大小、哈希与 WAV
        | 调用现有公共评分/幂等持久化逻辑
        v
TEST 评分记录 + TEST 私有最终录音
        |
        | 返回评分与诊断；尽力删除临时对象
        v
家长 TEST 页面显示反馈
```

正式实现必须建立与隔离探针分开的真实口语动作，例如：

- `createSpeakingDirectUpload`：为一条确定的 TEST take 签发上传票据；
- `scoreDirectUploadedSpeakingTake`：核验对象并进入公共评分流程；
- `cancelSpeakingDirectUpload`：在明确未评分时清理放弃的临时对象。

具体动作名可遵循现有代码命名调整，但职责不得合并为可上传任意路径的通用接口。真实录音不再限制为探针的三个固定档位，继续使用现有口语服务的最小有效 WAV 条件与 `700000` 字节上限，不提高容量上限。

临时对象使用服务端生成且不可由浏览器自由指定的前缀，例如：

`sherlock-english/tmp-speaking-direct/{data_kind}/{owner_id}/{take_id}.wav`

本阶段 `data_kind` 只能是 `test`。

## 5. 幂等与自动兜底状态机

所有路径必须共用同一个 `takeId`。前端不得因为网络超时创建新 take，以免重复评分、重复扣次数或重复录音。

### 可直接回退分块的情况

- 上传票据申请明确失败；
- COS PUT 在成功前明确失败；
- 服务端明确返回对象不存在、对象损坏、签名无效或完整性不匹配；
- 服务端确认该 `takeId` 尚未评分。

上述条件同时满足时，前端使用仍保存在内存中的同一份 WAV，通过现有分块链路提交同一个 `takeId`。

### 不得立即回退的模糊情况

- PUT 可能已经成功，但浏览器未收到响应；
- 评分请求超时或网络中断，服务端可能已经完成评分；
- 页面恢复后只知道请求失败，不知道评分是否落库。

此时必须先按同一 `takeId` 查询已有 take：

1. 已评分：直接恢复评分结果；
2. 未评分且临时对象仍存在：重试同一个直传评分动作；
3. 确认未评分且临时对象不可用：清理残余后才切换分块；
4. 状态仍无法判定：保留录音并提示重试，不创建新 take。

若两条链路都失败，浏览器保留本题录音，允许再次提交，不要求孩子重新录制。

## 6. 安全与数据治理

上传票据必须绑定并由服务端重新核验：

- 当前认证用户、家长 TEST 会话和所有者；
- `data_kind=test`；
- 课程 ID、版本、题号和尝试序号；
- `takeId`、唯一对象路径和文件 ID；
- 声明字节数、SHA-256 与允许的 MIME 类型；
- 签发时间和不超过 120 秒的过期时间。

同时遵守：

- 正式会话、儿童会话和隐藏课程不得调用本阶段直传动作；
- 浏览器不得接触长期 CloudBase/COS 密钥；
- 临时对象与最终录音保持私有，不生成公共下载链接；
- 后端不信任浏览器回传的任意对象路径；
- 日志不得输出签名 URL、会话令牌、录音正文或完整内部路径；
- 评分成功、明确失败和取消均尝试清理临时对象；另保留受限的过期对象清理机制；
- TEST 结果继续与 formal 隔离，不更新学习档案、错题库或正式能力分析。

## 7. TEST 诊断与可观测性

家长 TEST 页面为每题显示：

- 实际传输方式：`直传` 或 `分块兜底`；
- 客户端哈希耗时；
- 票据申请耗时；
- COS 上传耗时；
- 服务端对象校验耗时；
- 评分耗时；
- 从点击“提交评分”到反馈出现的总耗时；
- 临时对象清理结果。

诊断只在家长 TEST 页面启用，不进入孩子正式页面。面向家长的错误信息使用稳定错误码和简短说明，不暴露密钥、签名或内部堆栈。

服务端日志需能按 `takeId` 串联签发、上传确认、评分、兜底与清理，但不得新增永久保存录音内容的诊断副本。

## 8. 验证与验收

### 自动验证

- 上传票据仅允许家长 TEST 会话；
- 路径、所有者、题目、大小、哈希、类型和过期时间均不可被篡改；
- 超过 `700000` 字节及无效 WAV 被拒绝；
- 同一 `takeId` 的重复请求返回同一评分，不重复调用评分提供方；
- 模糊超时先查 take，不直接创建新 take；
- 明确直传失败能够用同一录音和同一 `takeId` 回退分块；
- 成功、失败和取消路径均覆盖临时对象清理；
- 现有 `scoreSpeakingTake`、`uploadSpeakingChunk` 和 `scoreUploadedSpeakingTake` 行为保持通过；
- 正式入口、隐藏课程拒绝规则及既有 test/formal 隔离保持通过。

### 真机验收

在无 VPN iPad Safari 上，从 GitHub Pages 家长 TEST 入口完成整节 8 题口语并最终提交：

- 8/8 题取得评分；
- 无重复评分、无丢题、无重复扣次数；
- 8 条 TEST take 与课程提交状态正确；
- 8 份 TEST 私有最终录音可核验；
- 每题传输方式及分阶段耗时完整可见；
- 直传临时前缀最终对象数为 0；
- 单题反馈总耗时中位数不超过 5 秒；
- 任意一题反馈总耗时不超过 8 秒。

若出现自动兜底但课程仍完成，只能说明功能连续性通过，不能认定直传链路完成验收。必须记录兜底题号、错误域和服务端状态，修复后重新完成直传验收。

真机 TEST 数据不得写入学习档案，也不得据此更新孩子的正式英语能力结论。

## 9. 灰度、停止条件与回滚

直传能力由服务端 TEST 专用开关控制，默认范围仅为 GitHub Pages 家长 TEST。关闭开关后，前端立即全部使用现有分块上传，不要求修改或重新部署腾讯云正式入口。

遇到以下任一条件停止扩大范围：

- 需要升级套餐、开启超额付费或暴露长期密钥；
- 无法可靠区分“已评分”和“可安全回退”；
- 出现重复评分、重复扣次数、录音丢失或 test/formal 串写；
- 临时对象无法可靠清理；
- 正式入口或其他应用受到影响；
- 8 题验收性能未达到既定门槛。

本阶段通过只授权形成“TEST 直传链路可用”的结论，不自动授权正式入口切换。正式切换、直接复用最终对象或评分函数按对象读取，均需另立设计并再次批准。

## 10. 最可能错误的判断

本设计最可能高估了上传链路对总反馈耗时的影响。即使直传显著降低浏览器传输开销，讯飞 ISE 评分及后端重复读写仍可能使中位数超过 5 秒；届时本阶段的主要收益将是稳定性和错误可诊断性，而不是明显提速。
