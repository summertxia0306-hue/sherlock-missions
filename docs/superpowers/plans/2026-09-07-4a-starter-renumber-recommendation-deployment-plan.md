# 4A Starter 编号迁移、推荐窗口与正式部署实施计划

## 目标

按已批准的方案 A，将新教材 Starter 五组课程从 D07-D11 迁移为 D01-D05，撤出旧教材 D01-D06 的现行课程资产；在听力、口语入口保持“推荐前 2 课 + 推荐课 + 推荐后 2 课”的窗口，并把推荐课按钮显示为“推荐开始”。完成内容、音频、manifest 与应用校验后，部署到当前唯一正式入口 Streamlit；CloudBase formal 保持关闭。

## 不变量

- 不删除或改写历史成绩、录音、数据库记录和 Git 历史。
- 听力与口语分别根据各自 formal 完成记录计算推荐课。
- 不制造完成记录；线上验证不提交 test/formal 学习结果。
- 保留现有 CloudBase 环境、正式开关、认证、数据治理和口语门控。
- 不提交工作区内既有用户改动和新教材原始文件。

## 实施步骤

1. 先补充编号、目录、推荐窗口和按钮文案的回归测试，并确认旧实现出现预期失败。
2. 修改 Starter 生成器，生成 D01-D05 正式课程，定向清理当前课程源、草稿、课程音频目录及 manifest 中的 D06-D11 旧条目。
3. 将三份课程批次文档同步改为 D01-D05，并明确旧教材资产仅由 Git 历史保留。
4. 调整听力和口语推荐卡按钮：推荐课显示“推荐开始”，其他课保持“开始”。
5. 重建 94 个听力音频和 40 个口语音频，刷新 manifest，并同步 Web 与云函数内容。
6. 运行 Python、Web、云函数、类型检查、构建、音频解码、题量计分、教材范围和敏感信息校验。
7. 创建独立提交并推送，不纳入既有用户改动。
8. 推送独立提交，触发当前正式 Streamlit 应用更新；不修改 CloudBase 环境变量、云函数或 formal 开关。
9. 在线核对 D01-D05、S50/W50 推荐窗口、按钮文案和音频可用性；只浏览和打开课程，不提交任何结果，形成部署证据报告。

## 回滚

应用与课程源均由独立 Git 提交保留，可按提交回退；CloudBase 部署不执行数据库删除或迁移。出现线上验证失败时停止正式验收并恢复上一份已验证构建。
