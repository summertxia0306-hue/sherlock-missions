# 目标技术与内容架构

## 1. 原则

- 一个 PWA，多功能模块；
- 一份课程源，不双写；
- 内容、程序、私有数据分离；
- 服务端执行正式数据边界；
- 后续增加模块不修改现有模块内部逻辑；
- 先满足一个孩子的稳定使用，不建设过度通用的平台。

## 2. 目录建议

```text
English-Learning/
├─ web/
│  ├─ src/core/
│  ├─ src/modules/listening/
│  ├─ src/modules/speaking/
│  ├─ src/modules/parent/
│  └─ src/modules/vocabulary/   # 未来
├─ cloudfunctions/
│  ├─ submit-result/
│  ├─ parent-auth/
│  ├─ parent-results/
│  ├─ score-speaking/
│  └─ recording-access/
├─ content/
│  ├─ listening/
│  ├─ speaking/
│  ├─ curriculum/
│  └─ manifests/
├─ static/audio/
├─ schemas/
├─ tools/
├─ tests/
├─ docs/
└─ legacy-streamlit/            # 过渡期
```

最终目录可根据现有仓库模式小幅调整，但边界不得改变。

## 3. CloudBase 隔离

与 24 点共用环境但不共用资源命名：

```text
静态路径：/sherlock-english/
云函数：sherlock-*
数据库集合：sherlock_*
云存储：sherlock-english/*
日志标签：sherlock-english
```

禁止修改 24 点的静态路径、发布版本、数据或配置。

## 4. 共享核心

共享核心负责：

- 路由和 PWA；
- 学生身份与家长认证；
- 课程目录和推荐；
- 教材范围和 study pack；
- formal/test；
- 通用结果头；
- 录音和音频访问；
- 家长端；
- 错题与弱项查询。

## 5. 模块合同

每个模块必须自行提供：

- 课程 schema；
- 页面入口；
- 结果 payload；
- 完成判定；
- 自动测试；
- 家长明细渲染；
- CONTRACT 文档。

模块不能直接写数据库，只能通过共享提交服务。

## 6. 听力模块

第一版保持现有成熟行为：

- 课程列表和首个 formal 未完成推荐；
- 最多显示推荐课附近 5 课；
- 音频播放限制；
- 五类题型；
- 提交、得分和逐题订正；
- 儿童端不暴露原文、答案、考点标签或数字分数；
- 家长端显示完整结果。

## 7. 跟读模块

第一版保持：

- 6 repeat + 2 QA；
- 倒计时录音、自动停止、回放和确认；
- 科大讯飞 ISE；
- 三星正常通过；
- 未到三星可重试；
- 第三次后出现“先过这题”；
- 保留首读、末读、最高分、每次星级、弱词和 safety pass；
- 评分失败不消耗有效三次。

## 8. 未来单词模块

当前只预留：

- `module_type=vocabulary`；
- 与教材词条共享 `content_item_id`；
- 与 study pack 共享教材范围；
- 独立结果 payload；
- 可读取 formal 弱词作为复习来源。

正式立项后第一版可包含认词、听音选词、中英匹配、拼写和错词复现。间隔重复应采用成熟算法和库，不自行发明调度算法。

## 9. 内容来源

- 课程 JSON 和音频 manifest 继续版本化并进入 Git。
- 教材索引、总词库和必要教材来源进入 `content/curriculum` 或 `curriculum`。
- 课程引用教材对象，不复制多份词表。
- 新增十课只增加内容与音频，不修改核心程序。

## 10. 部署

- Web 构建产物部署到 CloudBase 静态托管独立路径。
- 云函数独立部署并使用环境变量。
- 数据库和云存储权限以最小权限配置。
- 发布脚本验证 ZIP/路径统一使用 `/`。
- 每次发布保留版本号、Git 提交、资源清单和回滚版本。
